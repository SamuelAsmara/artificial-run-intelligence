estimateThresholdSpeed had a fallback: with no sustained hard effort on
record, take the fastest run over twenty minutes and shade it down 6%. It
looks harmless. For an athlete who only ever runs easy, "the fastest run over
twenty minutes" is an easy run — so the fallback treated an easy pace as a
threshold pace and then made it slower still. The demo dataset put numbers on
it: prescribed easy paces of 8:15, 8:18, 8:30 and 10:29 per kilometre for
athletes whose actual easy pace is 6:45. The app was telling beginners to run
slower than they already run easily, and it compounds — run to those paces and
the next estimate is slower again.

The reason it produced nonsense is that it never looked at heart rate. The
main path does; the fallback inferred effort from speed alone, which only
works for somebody who does hard sessions — precisely the athlete who never
reaches it.

So it is gone. No qualifying effort now means no threshold pace, and the
callers already handled that: paceForWorkout returns null and describeSession
falls back to distance, so a session reads "8.0 km, easy" rather than carrying
an invented number. This is also what the field does — TrainingPeaks, WKO5,
GoldenCheetah and Final Surge all leave threshold pace as something somebody
enters, and intervals.icu computes a critical speed and still declines to
write it there.

The qualifying window widens from 35 minutes to 20, which is what Friel,
TrainingPeaks and Tredict accept and what most interval sessions actually are;
35 was excluding the hard efforts of everybody who trains hard twice a week. A
duration discount comes with it — threshold is about 95% of a best 20-minute
effort — because widening the window without one would have made every
threshold too fast, which is the same bug pointing the other way.

Also adds migration 0017. auth.users had one trigger, on INSERT, so
profiles.email was copied at signup and never updated again: an athlete who
changed their address kept the old one in profiles forever, and the coach's
roster labels people by it. A trigger rather than a write in the action,
because the address can also change from the dashboard or the admin API.
