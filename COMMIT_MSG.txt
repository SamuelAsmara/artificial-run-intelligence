make the planned-pace band tell the truth about interval sessions

The band itself was already there — a shaded window ±10 s/km around the
target, with a dashed centre line, drawn on the pace lane. Nobody had seen it,
because no demo run carried a pace stream and the whole chart fell back to
"second-by-second detail is only available for runs from intervals.icu". It
was correct and invisible.

Two things it got wrong once there was data to draw it against.

An interval session has no single target pace. The warm-up, the floats and the
cool-down all sit outside any window built around the reps, so a band across
the whole run reported failure on a session executed exactly as written.
targetBand declines to draw one, and per-rep targets are left as their own
piece of work — sessionShape already knows how to split a session, so the
data exists when the screen is ready for it.

And when the whole run fell outside the target, band.y clamped both edges to
the same boundary and Math.max(1, …) drew a one-pixel line with no
explanation — which reads as a rendering fault rather than as information.
That case is now an explicit edge marker with a label saying which side the
target is on.

The tolerance moves into a named constant shared with comparePlanned, so the
shaded window and the sentence underneath it cannot drift apart. Comparison
gains workoutType, which is how the chart knows what kind of session it is
looking at.

In the ordinary case the rendered output is unchanged: same rect, same
geometry, same dashed line.
